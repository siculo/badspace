01 · Il tempo logico

Il tick non è un orologio

Ogni nodo mantiene un tick T monotono e lo propaga alle partizioni tramite setTick(t).

03 · Scritture e commit

Commit non significa immediatamente visibile

T = 102
→
write(A)
→
commit()
→
setTick(103)
→
S(102) leggibile

Con commit

Lo snapshot finale contiene l'ultimo stato confermato nel tick.

Senza commit

Lo snapshot logico eredita lo stato confermato precedente. Le scritture non confermate non vengono pubblicate.

L'avanzamento del tick serializza la pubblicazione: uno snapshot finalizzato non può essere modificato retroattivamente.

10 · Lettura coerente

Un reader ottiene una SnapshotAcquisition

acquireSnapshot(partitionId, n, timeout) → SnapshotAcquisition

Condizione temporale

max(T − k, C) ≤ n ≤ T − 1

C = creationTick

Condizione di esistenza

R indefinito oppure n < R

R = removalTick

Il timeout è obbligatorio, positivo e misurato in tempo reale. L'acquisizione non muta il contenuto immutabile dello snapshot.

12 · Garbage collection

Quando si possono liberare le risorse?

1 · Storia esaurita

T − k ≥ removalTick

Nessun tick in cui la partizione esisteva è più nella retention.

2 · Nessun utilizzatore

0 acquisizioni valide
0 query in corso

Le acquisizioni scadute si chiudono quando tutte le query avviate terminano.

13 · Controlli preventivi

Esisteva ≠ È acquisibile

Esistenza logica

partitionExistsAt(id, n)

Verifica C ≤ n e n < R se R è definito. Proposta per le API.

Acquisibilità attuale

canAcquireSnapshot(id, n)

Verifica anche completamento e retention. Proposta per le API.

Sono controlli non vincolanti: il tick può avanzare tra verifica e acquisizione. acquireSnapshot() deve rivalidare atomicamente le condizioni.

Dopo la distruzione dei metadati storici, «non verificabile» non dovrebbe essere confuso con «mai esistita».

14 · Sistema distribuito

Un nodo avanza. Le partizioni non insieme.

Nodo
setTick(105)
→
Partizione A
T = 105
Partizione B
T = 104
Partizione C
T = 102

Ordine per partizione

Scritture, commit e avanzamento devono essere serializzati in modo deterministico.

Osservazione distribuita

Le transizioni fra partizioni non sono atomiche; reader distribuiti possono osservare tick diversi.

Su una singola partizione, pubblicazione degli snapshot e applicazione della rimozione non devono essere osservabili parzialmente.
Le invarianti da ricordare

Una semantica, cinque garanzie

01 · Monotonia

setTick avanza o resta invariato, mai indietro.

02 · Snapshot finali

S(n) rappresenta lo stato confermato alla fine di n.

03 · Finestra temporale

Nuove letture limitate da creazione, completamento, retention e rimozione.

04 · Rimozione differita

remove() diventa effettivo al prossimo vero avanzamento.

05 · Protezione delle query: la fine dell'acquisizione impedisce nuove query, ma lascia terminare quelle già accettate.
